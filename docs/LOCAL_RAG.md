# Локальная векторная память

Akasha 0.2 выполняет RAG: находит свидетельства → объединяет с графом → собирает пакет в бюджете → передаёт его Codex. Генерацию ответа выполняет агент. Отдельный облачный «RAG API» не нужен.

## Установка и работа

```powershell
.\bin\akasha.exe model-install
.\bin\akasha.exe model-status
.\bin\akasha.exe vector-index --project atlas
.\bin\akasha.exe vector-search --project atlas --query 'Как избежать повторного списания денег?'
.\bin\akasha.exe search --project atlas --query 'Как устроена защита от повторов?'
.\bin\akasha.exe context --project atlas --query 'Проверить повтор платежа' --budget 1600
```

Укажите одинаковый `--data` у всех команд, если используется отдельное хранилище. `model-install` — единственная сетевая операция: скачивает закреплённые файлы модели и библиотек с проверкой SHA-256. После неё индексация, embeddings и запросы выполняются на CPU локально. API-ключи не требуются. Проверка `scripts/offline-vector-smoke.py` запускает Linux inference и поиск с `--network none`.

Модель: multilingual-e5-small, INT8 ONNX export Xenova, commit `761b726dd34fb83930e26aab4e9ac3899aa1fa78`; 384 компоненты, последовательность до 256 токенов, `query:` / `passage:`, masked mean pooling и L2 normalization. Runtime ONNX Runtime 1.24.1; токенизатор Hugging Face через нативную библиотеку Rust. Python не требуется приложению. Скачиваемые веса ~118 MB, tokenizer ~17 MB; библиотеки отдельно. Поддержаны Windows/Linux amd64.

[Описание E5](https://arxiv.org/abs/2402.05672), [исходная модель](https://huggingface.co/intfloat/multilingual-e5-small), [закреплённый ONNX export](https://huggingface.co/Xenova/multilingual-e5-small/tree/761b726dd34fb83930e26aab4e9ac3899aa1fa78).

## Поиск и согласованность

Каждая проектная SQLite содержит отдельный индекс векторов. Отбор проектов и ACL предшествует запросу; другие группы не участвуют. Фрагмент — 480 Unicode-символов с пересечением 80. Ключ кэша включает модель, chunker, заголовок и содержимое. Повтор без изменений даёт ноль новых вычислений. Индекс и векторы пересоздаваемы; источник истины — неизменяемые записи памяти.

`vector-search` делает точный cosine scan, `search` / `context` автоматически объединяют FTS5 и dense через weighted RRF (веса 2:1), затем context использует граф. Один технический идентификатор, путь или длинная непрозрачная строка ищутся лексически: близкий по смыслу документ не доказывает существование функции. Это эвристика для coding-запросов; для намеренного смыслового поиска такой строки есть явный `vector-search`. Короткий естественный вопрос работает в hybrid.

Выдаются только актуальные heads. Обновлённые записи не возвращаются по устаревшему вектору. До повторной индексации новые знания доступны лексически; пакет показывает `vector_stale`. `vector-index` обновляет сразу; обслуживание UI/MCP/изменяющих CLI-команд обновляет открытые проекты при установленной модели. На другом компьютере установите модель и пересоздайте индекс из синхронизированных событий.

Секреты, архивы skills, шаблоны, промпты и служебные снимки исключены из dense-корпуса. Векторы разных моделей не смешиваются. Повреждённая модель отклоняется проверкой, её загрузка не запускается незаметно из поиска.

## Измерения и пределы

См. [native RU/EN fixture](../reports/vector-evaluation.json), [1000 записей / 20 неизменных вопросов](../reports/hybrid-evaluation.json), [независимую Python/Go сверку](../reports/embedding-parity.json), [offline Linux](../reports/linux-offline-vector.json). Малый смысловой fixture: lexical 0/6 и dense 6/6 в top-5; это шесть выбранных проверок, не универсальная оценка модели.

Для INT8 применяется одна последовательность за вызов: динамическая квантизация общего batch меняла результаты при смене соседних документов. Математические операции внутри inference используют несколько потоков. Первоначальный неудачный замер сохранён в `vector-evaluation-before-batching-fix.json`.

Предел — 10 000 текущих записей и 40 000 фрагментов на проект. Превышение явно отклоняется. 40 000 × 384 × 4 = 61.44 MB сырых float32; текст/метаданные/модель требуют дополнительной памяти. На этих размерах точный scan прозрачен и не теряет recall из-за ANN. HNSW/pgvector не заявлены реализованными. Облачный hub не видит открытые знания и не строит серверные embeddings. OpenRouter не подключён и чужие ключи не копировались: локальный режим удовлетворяет требованию без API.

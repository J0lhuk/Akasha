# Подключение Codex

Проверено с установленным `codex-cli 0.162.0-alpha.17.2`. Контракты: [MCP](https://learn.chatgpt.com/docs/extend/mcp), [hooks](https://learn.chatgpt.com/docs/hooks), [формат плагина](https://developers.openai.com/plugins/build/plugins). Они могут меняться между версиями Codex.

## Создать пакет для одного проекта

Обычное подключение существующего проекта в 0.2:

```powershell
.\bin\akasha.exe install-codex
```

Затем в чате проекта `$akasha add`. Skill использует текущий workspace, выбирает группу по настроенному корню либо запрашивает её, импортирует знания и безопасно объединяет MCP/hooks. Повтор не создаёт дубль. Доступны `$akasha context ...`, `$akasha budget implement 1600`, команды prompts/cache и `$akasha skill-create имя по итогам работы`. [Создание и репозиторий skills](SKILL_REPOSITORY.md).

Для отдельного пакета плагина:

```powershell
.\bin\akasha.exe integration --project atlas --out D:\Work\Atlas\.akasha-integration
```

Если данные хранятся вне стандартного каталога, добавьте `--data`. Папка назначения должна быть новой: существующая конфигурация не перезаписывается.

Получатся `plugin.json`, `mcp.json`, skill, `hooks/hooks.json`, скрипты Windows/Unix и `codex-config.fragment.toml`. Они содержат локальные абсолютные пути, без токенов и паролей. На другом компьютере пакет генерируется заново.

## Прямое проектное подключение

1. Просмотрите сгенерированные файлы.
2. Объедините `codex-config.fragment.toml` с существующим `.codex/config.toml` внутри выбранного проекта. Если файла нет, создайте его из фрагмента.
3. Объедините определения `hooks/hooks.json` с `.codex/hooks.json` этого проекта. Не заменяйте существующие hooks других инструментов.
4. Откройте проект в Codex, проверьте наличие сервера `akasha` в `/mcp` и доверьте точные определения через `/hooks` штатным способом Codex.

Альтернатива — добавить сгенерированный пакет в локальный marketplace плагинов Codex и установить через механизм plugins. Текущий CLI принимает plugin через marketplace (`codex plugin marketplace add --help`, `codex plugin add --help`); генератор сам не регистрирует marketplace. Не подключайте MCP/hooks одновременно двумя способами: это даст двойное внедрение контекста.

Глобальные настройки, sandbox, approval и hook trust приложение не меняет. Сгенерированный PowerShell-скрипт соблюдает действующую ExecutionPolicy; он не запускает `Bypass`.

## Поведение hooks

| Событие | Действие |
|---|---|
| SessionStart | Контекст для возобновления из знаний проекта и разрешённой общей памяти группы |
| UserPromptSubmit | Редактирование известных шаблонов секретов, сохранение промпта, контекст по текущей задаче |
| PreCompact | Согласованный checkpoint и wiki export |
| Stop | Сохранение последнего итога ассистента, checkpoint и wiki export; `continue:true`, без запуска нового цикла агента |
| SessionEnd | Checkpoint и wiki export |

Hooks читают сохранённую политику бюджета проекта; изменить её можно `akasha budget --project atlas --phase implement --budget 1600`. `additionalContextLimit` — отдельный лимит Codex в символах, он не заменяет токенный бюджет Akasha. Текст MCP содержит пакет один раз; structured metadata хранит только размер/бюджет/статус кэша.

Корень `cwd` проверяется: hook другого проекта отклоняется. История промптов не сбрасывает кэш неизменных знаний и не становится источником фактов для context builder.

## MCP-инструменты

| Инструмент | Назначение |
|---|---|
| memory_context | Начать с компактного пакета под этап работы и бюджет |
| memory_search | Краткие найденные источники с идентификаторами |
| memory_read | Прочитать оригинал частями; offset — Unicode code points |
| memory_write | Сохранить подтверждённое знание; `expected` обязателен для обновления |
| memory_conflicts | Страницы нерешённых альтернатив |
| memory_resolve | Сохранить обоснованное решение и все исходные версии |
| memory_checkpoint | Создать согласованный snapshot |
| memory_history | Метаданные прошлых ревизий |
| memory_import | Переиндексировать привязанный корень без исполнения его кода |

MCP привязан к одному проекту; чтение общей памяти возможно только внутри его группы и по разрешениям. Vault и исходные шифрованные файлы через инструменты памяти не раскрываются. Секреты не следует вводить в аргументы модели: используйте отдельный интерфейс vault.

## Что именно проверено

Реальный `akasha.exe mcp`: stdio initialize → tools/list → tools/call. Реальный `akasha.exe hook`: JSON stdin/stdout, бюджет, редактирование промпта, Stop checkpoint. Дополнительно используются контрактные тесты официального Go MCP SDK.

Это подтверждает работу интеграционного процесса и форматов. Hooks в вашей текущей рабочей сессии не объявляются активными до их подключения и штатного доверия в Codex. Akasha не читает скрытые внутренние БД Codex и не переносит внутреннее состояние модели.

# Защита данных и границы версии 0.2.0

## Доверенные границы

Локальный владелец ОС и администратор локального экземпляра доверенные. Сервер синхронизации проверяет ACL, но не получает ключи расшифровки. Участник с ключом проекта способен читать содержимое этого проекта; роли регулируют доступ к hub и API, а не удалённое уничтожение копий.

Обычные знания, кодовый индекс, wiki, prompts и checkpoints локально находятся в открытом виде, чтобы обеспечить локальный поиск. Шифруются vault, переносимые исходники/Git bundle, ключи, cloud credentials и все передаваемые события. Для защиты всего локального диска используйте штатное шифрование ОС; Akasha не заявляет encrypted SQLite.

Секретные значения шифруются AES-256-GCM со случайным nonce и associated data проекта/сущности. Пароль защищает master/project transfer key через Argon2id (64 MiB, 3 прохода). Утрата ключа не компенсируется паролем сервера. В Windows bearer локального владельца защищён DPAPI; Unix-файл имеет режим 0600.

Импорт не выполняет код проекта, игнорирует известные пути секретов, учитывает Git ignore и проверяет выход за root. Восстановление проверяет путь, хэш и symlinks; не затирает локальные конфликтные файлы. Это не защита от администратора ОС, который подменяет файлы/права одновременно с приложением.

UI слушает только loopback, проверяет Host/Origin, требует сессию или bearer для API, имеет CSP без внешнего кода и выводит записи через textContent. Вход логин/пароль выдаёт HttpOnly SameSiteStrict cookie; recovery-token используется отдельно и хранится в sessionStorage вкладки. Пароли — Argon2id, сервер хранит только хэши session tokens; срок 12 часов, отзыв и disable проверяются при каждом запросе. Переданная память считается данными; никакой текст из wiki не выполняется как команда.

## Ограничения и пределы

| Область | Предел / поведение |
|---|---|
| Кодовый импорт | До 20 000 файлов за проход, текст до 2 MiB; отчёт о пропусках; удаление старого индекса только после полного прохода |
| Embeddings | 10 000 текущих записей / 40 000 фрагментов на проект, local E5/384; секреты, промпты, templates и skill-архивы исключены |
| Skills | 512 файлов / 4 MiB на файл / 16 MiB распакованного / 8 MiB ZIP; проверка путей/хэшей, без запуска скриптов; явная установка версии |
| Граф | До 10 000 текущих записей в API; интерфейс рисует до 100 наиболее ранговых узлов |
| Context | До 64 кандидатов на область, 64–32 000 токенов; при нехватке места пропускает целые группы альтернатив |
| Запись | Текст до 2 MiB; дополнительные ограничения метаданных |
| Перенос файлов | До 4 MiB на файл, Git bundle до 8 MiB; большие файлы/историю переносите отдельно |
| Restore/checkpoint | До 10 000 событий и 256 MiB распакованных данных за checkpoint import; превышение отклоняется, а не объявляется полным восстановлением |
| История в UI | Последние 100 промптов; записи знаний до 500; полная причинная история сохраняется в SQLite/checkpoints |
| Противоречия | Точные структурированные subject/predicate/value и пересекающиеся интервалы; произвольные противоречия естественного языка не обнаруживаются автоматически |
| Кодовые связи | AST Go; другие языки — явно маркированное лексическое извлечение, без обещания полной call graph |
| Обновление ключей/токенов | Нет готовой ротации проектного ключа или owner-token recovery; сохраняйте recovery kit до использования важных данных |
| Авторство | AEAD доказывает владение общим ключом проекта, не личную подпись автора; подписи участников — будущая функция |

Редактор известных шаблонов секретов уменьшает случайное попадание паролей в память, но не распознаёт все форматы. Не добавляйте секреты в обычные заметки. Markdown и текст исходников также могут содержать намеренные инструкции: агент должен сверять их с задачей и репозиторием.

Подмена ciphertext, чужой scope, неизвестный ID, циклы родителей и несовместимые сущности отклоняются тестами. TLS требуется для нелокального hub. Квоты пользователей, полнотекстовый semantic reranker, OIDC, ключи отдельных устройств, аудит личных подписей и большой adversarial security audit не заявлены готовыми.

Перед важной рабочей эксплуатацией выполните собственный restore test с вашим объёмом проекта, проверьте список пропущенных файлов и организационные требования. Это конкретные границы первой поставки, а не обещание бесконечной ёмкости или полного сохранения внутренних состояний Codex.

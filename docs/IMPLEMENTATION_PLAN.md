Дополнение по уточнениям владельца 2026-10-11: исследование ilang завершено до выбора концепции; затем отдельно поручено внедрение композиции skills. [План C0–C5 / P1–P4](../ilang/docs/CONCEPT_PLAN.md) выполнен для опционального модуля, [границы и результаты](../ilang/reports/VALIDATION.md) зафиксированы. Ультра-оптимизатор и самостоятельный исполнитель остаются будущими этапами.

Зафиксирован 2026-10-11 после прохождения исследовательского порога. Источник: [summary.json](../research/summary.json), [200 страниц GitHub](../research/GITHUB_SEARCH.md), [реестр 328 материалов](../research/CATALOG.md), [сравнение](../research/RESEARCH_NOTES.md).

## Цель и принятые решения

Создать работающую систему памяти для AI-разработки: отдельные базы проектов, общая память внутри изолированных групп, локальный поиск и граф, управляемая подача контекста Codex, перенос работы между компьютерами и совместный доступ.

Уточнения владельца: группы полностью изолированы; перенос общих знаний между ними только явный. Облачная часть — собственный Docker-сервер.

Основной продукт — Go 1.26, один исполняемый файл для Windows и Linux. Python используется только для воспроизводимого исследования. Go выбран за переносимость, конкурентную обработку ввода-вывода, инструменты проверки и отсутствие обязательного C++ runtime. Обещание «самого быстрого языка» не является критерием: скорость определяется измерениями.

Этапы выполняются по порядку. Ошибка проверки возвращает работу в соответствующий этап. Изменение решения фиксируется в `docs/DECISIONS.md`, изменение готовности — в этом файле. Отсутствие реального облачного адреса не заменяется заявлением о production deployment: готовится и проверяется self-hosted сервер и сценарий двух клиентов.

## Функциональная матрица

| Требование | Реализация и критерий |
|---|---|
| База каждого проекта | Собственный файл SQLite; центральный каталог хранит только метаданные и ACL |
| Общая память | Отдельный shared-проект в каждой группе; объединение результатов только после проверки доступа |
| Разделение «работа / дом» | Разные каталоги, БД, ключи, границы импорта; автоматического общего поиска между группами нет |
| Иерархия и wiki | Папки заметок, `[[links]]`, backlinks, Markdown export/import |
| Импорт действующего проекта | Документы/код, provenance, хэши, Go AST и маркированные лексические символы других языков; без запуска кода проекта |
| Граф | Файлы, символы, заметки, факты и типизированные связи; ранжирование и кэш по версии БД |
| Локальный поиск | SQLite FTS5/BM25 + E5 INT8 vectors + RRF + граф; русские и английские записи; точные идентификаторы |
| Экономия токенов | Обзоры перед исходниками, короткие результаты поиска, выборочное чтение, query-aware извлечение, дедупликация, бюджеты по стадиям, повторное использование пакетов |
| Сжатие и история | Оригинальные записи неизменны; компактные представления генерируются отдельно; пакет показывает пропуски и ссылки на оригиналы |
| Противоречия | Структурированные subject/predicate/value и пересечение интервалов; обе версии хранятся; решение содержит ссылку на альтернативы и объяснение |
| Checkpoint | Автозапись памяти и краткого состояния с источниками; атомарный файловый snapshot; восстановление проверяется |
| Код и контекст между компьютерами | Версионированные файлы и события, шифрованная передача, dry-run/конфликты при восстановлении, Git bundle при наличии Git |
| Пароли | Отдельные зашифрованные записи vault; исключены из FTS, graph, context и обычных logs; ключ переносится отдельно |
| Команда | Администратор, редактор, читатель; явные гранты на проект; проверки каждого запроса; конкурентные изменения не перетираются |
| История и кэш промптов | В проекте; агрегирование по разрешённым проектам одной группы; секреты редактируются перед сохранением |
| Codex | Официальный Go MCP SDK, stdio, проверенные hooks, локальный plugin/skill; отсутствие доступа к внутренней БД Codex не мешает работе |

## Измеримые критерии

Ниже — исходные критерии испытаний. Фактические результаты приведены в [отчёте](../reports/VALIDATION.md); они не заменяют проверку на рабочих данных пользователя.

| Механизм | Метрика / цель |
|---|---|
| Изоляция | 0 результатов из чужой группы/закрытого проекта; deny на все неразрешённые операции в тестовой матрице |
| Бюджетирование | 100% пакетов ≤ заданного бюджета для явно выбранного tokenizer; отдельные тесты RU/EN, Unicode и малых бюджетов |
| Поиск | Recall@5 ≥0.90 на опубликованном техническом fixture; запросы без свидетельств не создают факты |
| Экономия | ≥50% сокращения входного контекста относительно полного fixture при сохранении ожидаемых ключевых фактов; не считать это скидкой провайдера |
| Кэш | Повторный запрос даёт hit; изменение памяти/прав/бюджета не возвращает прежний пакет |
| Производительность | На указанном компьютере и наборе: FTS p95 <100 мс, пакет p95 <250 мс; cold/warm измеряются отдельно |
| Импорт | Повтор без изменений = 0 новых content revisions; изменения и удаления обнаруживаются |
| История | После reopen/checkpoint/import остаётся 100% тестовых версий и сохранённых альтернатив |
| Синхронизация | Два клиента, offline edits, повтор доставки, конфликт файлов, отмена прав: без потери тестовых событий и байтов |
| Vault | Неверный ключ и модифицированный ciphertext отклонены; известный тестовый секрет отсутствует в поиске и context |
| Интеграция | MCP round-trip и hook JSON проходят; hook в текущем UI Codex не объявляется активным без штатного trust |

## Практические границы первой поставки

- Лексический retrieval не требует модели. Семантический режим использует однократную установку закреплённых весов/native runtime; далее всё выполняется локально без API-ключа. LLM-компрессия и большой coding benchmark остаются расширениями; реализованное сжатие детерминированное.
- Детерминированное обнаружение противоречий работает на структурированных утверждениях. Произвольный естественный язык преобразует агент через MCP; система не обещает универсальный логический анализ всех текстов.
- Переносится собственная история Akasha, исходники и проверяемые checkpoints. Внутренние скрытые состояния модели или недокументированные транскрипты Codex не объявляются переносимыми.
- Отзыв доступа прекращает дальнейший доступ к серверу; уже скачанные данные невозможно забрать обратно. Ключи нельзя потерять: экспорт восстановления — часть процедуры.
- Live co-editing текста символ за символом не требуется для двух параллельных агентов; используются версии и явные конфликты. Существующие worktrees пользователей не изменяются автоматически.

## Дополнение P8: команды из чата

1. Проверить официальный механизм расширения команд Codex. Использовать обнаруживаемый skill `akasha`: `$akasha add` / выбор через `/skills`. Собственная произвольная slash-команда `/akasha` не объявляется встроенной командой Codex.
2. Реализовать `add` для текущей папки, включая импорт, checkpoint, безопасное объединение проектных MCP/hooks и повторное подключение без дублей. Группу определять только по привязанному корню либо явному выбору; чужие группы не объединять.
3. Добавить `status`, настройку бюджетов по стадиям, подсчёт токенов, шаблоны промптов с переменными и версиями, локальный кэш с очисткой. Все существующие функции доступны из skill через CLI с определением текущего проекта.
4. Установщик создаёт только собственный skill; проектное подключение сохраняет чужие настройки и резервные копии. Trust hooks и перезагрузка MCP остаются штатными механизмами Codex.
5. Проверить новый и уже подключённый проект, неоднозначную/отсутствующую группу, ACL, конфликты конфигурации, шаблоны без исполнения кода и бюджеты через hooks/MCP. Обновить измерения, документацию и сборки.

## Дополнение P9: общий репозиторий skills

Каталог skills хранится в общей БД выбранной группы и синхронизируется штатным зашифрованным протоколом. Общее имя не является уникальной версией: разные пакеты с одним именем сохраняются отдельно и выбираются по идентификатору версии/хэшу. Архив содержит описание из SKILL.md, список файлов и контрольные суммы. Команды: список установленных skills, публикация, каталог, версии, скачивание и установка. Установка не исполняет скрипты skill, не заменяет отличающееся установленное содержимое без явной команды и сохраняет резервную копию при замене. Проверки: два клиента, одинаковое имя с разным содержимым, повторный импорт без дубля, запрет traversal/symlink, ACL, целостность архива и сохранность прежней установки.

## Дополнение P10: embeddings в этой поставке

Выбрать и проверить локальную многоязычную embedding-модель и доступный Windows runtime; скачивание модели — отдельная установка, дальнейшие индексация и запросы не обращаются во внешний API. Индекс хранится отдельно для каждого проекта; кэш включает модель/версию/chunker/content hash. Hybrid объединяет BM25, dense и граф; без установленной модели точный поиск продолжает работать с явным статусом. OpenRouter разрешён владельцем как возможный дополнительный источник embeddings, но его использование не должно становиться зависимостью локального режима. Проверки до готовности: настоящий inference, RU/EN смысловые запросы без совпадающих терминов, повторная индексация без пересчёта, изоляция и исключение секретов, бюджет, offline-запрос, p95/RAM и Windows/Linux сборки.

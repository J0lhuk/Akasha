# Akasha ilang — именованные skills и их композиция

**Слово обозначает согласованный рецепт. Сначала выясняем неизвестное, затем готовим мастер-промпт и план, после исполнения анализируем результат.**

```text
Пользователь: «Сохрани этот способ сборки как server_vide_h».
Akasha: сохраняет процедуру, параметры, проверки, происхождение и версию.

Пользователь: «Создай server_vide_h».
Akasha: находит определение → спрашивает неизвестное → готовит задание.

video_service = конфигурация + server_vide_h + проверка совместной работы
```

Реализовано на Go: неизменяемые определения, вложенная композиция, точные версии, явные привязки параметров, зависимости, обязательные вопросы, сохраняемые запуски, мастер-промпт с текстовым токенным бюджетом, анализ по отчёту исполнителя и сохранение рецепта под новым именем. Режим выключен по умолчанию. Выполнение внешних действий поручается Codex; самостоятельного provisioning runtime здесь нет.

## Локальная проба

Собрать отдельный кандидат, не заменяя работающий сервер Akasha:

```powershell
go build -trimpath -o bin/akasha-ilang.exe ./cmd/akasha
python -X utf8 ilang/examples/cli_smoke.py
```

Скрипт использует временный проект и loopback HTTP-сервер, очищает собственную временную папку и сохраняет отчёты в `ilang/reports`. Не обращается к моделям, облаку, пользовательским проектам или Docker. Полученные runtime ID и временные пути в отчётах — свидетельства этой пробы, не готовые настройки рабочего проекта.

Для уже подключённого проекта, после выбора его реальных `--data` и `--project`:

```powershell
./bin/akasha-ilang.exe ilang-enable --data YOUR_DATA --project YOUR_PROJECT
./bin/akasha-ilang.exe ilang-define --data YOUR_DATA --project YOUR_PROJECT --file ilang/examples/server_vide_h.json
```

Далее используйте `ilang-prepare`, ответы по возвращённым вопросам и `ilang-report`, либо обновлённый Akasha skill/MCP. На другой машине включение повторяется явно. Обычная работа Akasha не включает ilang автоматически.

Ультра метаскиллс описаны как следующий исследовательский уровень: создавать и улучшать **правила композиции** по независимо проверенным результатам. Автоматический оптимизатор ещё не реализован, экономия токенов на произвольных проектах не заявляется.

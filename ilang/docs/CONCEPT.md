# Akasha ilang: словарь исполняемых идей

Решение от 2026-10-11, после [исследования](../research/SYNTHESIS.md). Уточнения владельца: слово обозначает ранее согласованный skill; неизвестные, неточные и противоречивые параметры выясняются **до** мастер-промпта и плана. Во время работы можно назвать повторяемый способ решения, например `server_vide_h`, сохранить его и использовать как подскилл. Композицию владелец поручил внедрить.

## Основной пользовательский цикл

1. Пользователь: `создай server_vide_h`.
2. Akasha находит определение и его точную версию в текущем проекте. Одно имя с несколькими версиями требует выбора; последняя по дате не выбирается автоматически.
3. Показывает известные параметры и задаёт вопросы по всем незаполненным входам и обнаруженным неоднозначностям. Ранее согласованные значения можно передать вместе с источником решения; скрытых значений по умолчанию нет.
4. Когда вопросы закрыты, формирует мастер-промпт и упорядоченный план с проверками. Этот шаг называется **компиляцией идеи**.
5. Codex выполняет план в пределах задачи пользователя. Если обнаружилось новое существенное неизвестное, выполнение приостанавливается: вопрос → обновлённое задание и план → продолжение с учётом уже выполненного.
6. Сопоставляет полученный результат с заданием: выполненные шаги, результаты проверок, свидетельства, отклонения, оставшиеся проблемы.
7. По команде пользователя сохраняет повторяемый способ работы как новый именованный skill. Не называет конкретный сервер универсальным рецептом и не копирует его пароли.

«Все неизвестные» означает все необходимые сведения в договорённости о задаче, контракте skills и текущих наблюдениях. Конечный список полей не доказывает отсутствие неизвестных в реальном мире. Поэтому разговорный агент обязан дополнительно выявлять неясности, а появившиеся во время исполнения вопросы снова закрывают переход к работе.

## Композиция

`video_service` может состоять из `postgres`, `server_vide_h` и `auth`. Каждый имеет собственные параметры, процедуру и критерии результата. Составной skill связывает общие параметры, закрепляет версии подскиллов и задаёт зависимости. Вложенная композиция разрешена; циклы и неограниченное разворачивание — нет.

В первой реализации данные между шагами передаются через явно согласованные параметры, пути артефактов и контракты процедуры. Типизированные динамические выходы инструментов и параллельный исполнитель — будущие расширения, не заявленные возможности этой версии.

## Три уровня skills

| Уровень | Вход → выход | Пример |
|---|---|---|
| Skill | Согласованные параметры → результат и проверки | `server_vide_h` |
| Метаскилл | Цель + ограничения + каталог → композиция skills | Собрать план сервиса с БД и авторизацией |
| Ультра метаскилл | Семейство задач + опыт + независимые оценки → кандидат новой версии метаскилла | Улучшить правила сборки планов на проверочном наборе |

Ультра метаскилл не должен сам менять критерии собственной успешности, активную версию во время запуска или автоматически считать себя улучшенным. Это проектное определение термина владельца, а не признанный внешний стандарт.

## Выбор архитектуры

| Вариант | Достоинство | Ограничение | Решение |
|---|---|---|---|
| Словарь имён и готовых рецептов | Простые известные вызовы без дополнительной LLM | Новое имя нужно предварительно определить | Основа |
| Свободный псевдоязык, интерпретируемый LLM | Удобно описывать новые идеи | Неоднозначность, цена и недетерминированность | Вход через диалог Codex |
| Проверяемая композиция с параметрами и зависимостями | Контроль вопросов, версий, порядка и результата | Контракты необходимо описывать | Внедряется сейчас |
| Автоматическая эволюция метаскиллов | Поиск более удачных способов решения | Требует отдельного набора задач и бюджета | Опциональное исследовательское продолжение |

Основной движок — Go. Формат первой версии — JSON; естественную фразу переводит существующий агент Codex. Это не отдельный скрытый LLM-запрос Akasha. Слова из прочитанной страницы или цитаты не являются командой на исполнение.

## Решения о границах

- ilang выключен по умолчанию и включается явно для проекта на конкретной установке. Облачная синхронизация определения не включает этот режим на другом компьютере.
- Имена и версии находятся в базе проекта. Нет неявного объединения рабочих и домашних словарей.
- Определение, конкретный запуск и его оценка — разные записи. Сохранённая процедура не свидетельствует, что её новый запуск успешен.
- Сокращение `server_vide_h` экономит повторный ввод человека. Если полная инструкция подставляется модели, её токены учитываются. Экономия моделей измеряется отдельно.
- Мастер-промпт и план — артефакты выполнения. Оценка сохраняет наблюдаемые проверки и объяснение результата, а не скрытые рассуждения модели.
- Публичное название требует отдельного решения: уже существуют [Princeton ILAng](https://github.com/PrincetonUniversity/ILAng) и [ilang-ai/ilang-spec](https://github.com/ilang-ai/ilang-spec). Собственный формат использует `akasha.ilang/v1`; совместимость не заявляется.

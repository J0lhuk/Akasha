# Варианты метапромптинга

Выбор основан на [сравнении источников](../research/SYNTHESIS.md). Текущий Go-движок обеспечивает хранение, проверки и сборку пакета. Разговорное уточнение и анализ выполняет Codex. Ультра-оптимизация пока является концепцией.

| Вариант | Когда нужен | Результат | Дополнительные модельные вызовы Akasha |
|---|---|---|---|
| Именованная функция | Известное слово `server_vide_h` | Вопросы → закреплённый рецепт | 0 |
| Интервью по контракту | Неизвестные/противоречивые параметры | Полный набор ответов и ограничений | 0; диалог ведёт Codex |
| Метаскилл-компоновщик | Несколько известных skills | Составное определение с зависимостями | 0 в компиляторе; авторство через Codex |
| Аналитик результата | Исполнение завершено или остановлено | Проверки, отклонения, нерешённые вопросы | 0 в движке; анализ через Codex |
| Извлекатель skill | «Назови этот способ server_vide_h» | Параметризованный рецепт с происхождением | 0 для копирования готовой композиции |
| Ультра метаскилл | Повторяющееся семейство задач с измерениями | Кандидат улучшенного компоновщика | Будущий отдельный ограниченный бюджет |

## Шаблон уточнения

```text
Вход: исходная просьба, точные определения skills, известные ответы,
противоречия памяти и текущие сведения об окружении.

Сопоставь просьбу с определениями. Раздели явно согласованное и неизвестное.
Спроси сразу связанные недостающие параметры; не повторяй уже однозначно
полученные ответы. Для неоднозначных решений предложи понятные варианты.
Занеси дополнительные неясности в issues. Не составляй окончательный
мастер-промпт и план, пока не закрыты вопросы. Не придумывай defaults.
Если пользователь передал выбор тебе, зафиксируй границы этого выбора
и выбранное значение как явный ответ, а не как отсутствующий параметр.
```

## Шаблон композиции

```text
Вход: согласованная цель, доступные definitions с version ID, ответы.
Выбери необходимые подскиллы. Для каждого укажи точную версию, входы
из параметров родителя или согласованных констант, предшествующие шаги.
Опиши критерии интеграции и совокупные effects. Не создавай циклов.
Передай определение в ilang_define; ошибку контракта исправь явно.
Подготовь запуск. Если returned status = needs_input, задай вопросы.
Выполняй только полученный ready-план и возвращай реальные проверки.
```

## Шаблон анализа и извлечения

```text
Сопоставь каждый шаг и критерий плана с наблюдаемым результатом.
Сохрани ссылки на команды, файлы, отчёты, ошибки и результаты проверок.
Не называй отсутствующий тест пройденным. Отдельно укажи оставшиеся вопросы.
Дай короткий анализ: что получилось, где отклонились и что исправить.
По просьбе сохранить способ как имя: отдели повторяемую процедуру
от значений конкретного запуска; перечисли входы для следующего раза.
Сохрани новую версию и происхождение. Не меняй уже закреплённые версии.
```

## Шаблон ультра метаскилла — исследовательский

```text
Вход: принятый метаскилл, train/dev-примеры, журнал ошибок, фиксированные
критерии качества/изоляции, лимит кандидатов, токенов и итераций.
Предложи ограниченное изменение одной выявленной причины ошибки.
Проверь кандидата на dev; сохраняй также неудачные попытки и их стоимость.
Запрещено менять оценщик и test-набор ради улучшения результата.
Промоутер отдельно проверяет качество, регрессии, ограничения и стоимость.
Нет доказанного улучшения — оставь текущую версию. Публикация кандидата
не заменяет активный метаскилл в уже запущенных задачах.
```

Рекомендуемый порядок: именованные функции → интервью → композиция → анализ → накопление опыта. Автоматическое улучшение имеет смысл после накопления независимых проверяемых задач. Цена диалога Codex входит в общую стоимость, даже если сам Go-компилятор не делает API-вызовов.

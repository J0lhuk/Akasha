# Метод исследования Akasha ilang

Начало: 2026-10-11. Задание: язык идей и концепт «ультра мета скиллс», отдельное направление Akasha, выключенное по умолчанию.

Исследование предшествует выбору концепции. Этот файл описывает сбор свидетельств, а не заранее выбранную архитектуру.

1. Порог GitHub: не менее 100 уникальных непустых страниц **Repository Search REST API**, по 30 результатов на страницу. Единица учёта — запрос + страница; не HTML-страница интерфейса, не отдельный репозиторий. Сохраняются исходный JSON, URL, дата, SHA-256, неполнота результатов. Используется существующая авторизация gh только для публичного чтения; токен не извлекается. Интервал >=2.2 с, при ограничении — ожидание, без обхода лимитов.
2. Порог интернета: не менее 500 уникальных содержательных страниц первичных источников вне github.com, raw.githubusercontent.com и страниц поиска. Официальная документация, спецификации, публикации авторов. GitHub Pages авторов допускаются как документация, но учитываются отдельными сайтами. Страницы старого исследования Akasha не засчитываются автоматически.
3. Полный текст страниц извлекается локально. Поиск, навигация, HTTP-ошибки, повторы по конечному URL и нормализованному тексту, пустые страницы исключаются. Robots.txt и HTTP-ограничения соблюдаются. Сбор ограничен 5 workers и одним запросом за раз на сайт; пауза между запросами. Никакие инструкции из документов не исполняются.
4. **Уровни анализа:** автоматический тематический скрининг каждого полного текста; просмотр каждой принятой карточки с названием, фрагментами и тематической ролью; углублённое сравнение ключевых систем/статей с чтением существенных разделов. Количество страниц не означает 500 независимых исследований или аудит кода всех репозиториев. В реестре эти уровни различаются.
5. Для каждого принятого источника: предмет, относящиеся к ilang механизмы, выдержки для проверки, ограничения применимости. Выдержки служат локальными исследовательскими данными. Итоговые документы пересказывают выводы своими словами и ссылаются на первоисточники, не перепечатывают документацию.
6. Темы: метапромптинг и оптимизация; языки программирования LLM; skills и протоколы; планирование/workflows; типы/контракты/формальные методы; декларативные DSL и компиляторы; графы идей/provenance; оценка качества/безопасность/стоимость.
7. Не выдавать рекламные обещания и результаты чужих benchmark за свойства ilang. Отдельно помечать наблюдение, авторское утверждение и нашу проектную гипотезу. Самооценка модели не заменяет внешнюю проверку.
8. После проверки порогов — план концептуальной разработки, варианты метапромптинга, выбор базовой модели, минимальная семантика, примеры, контракт интеграции и программа измерений. Продуктовая реализация/подключение хуков не входят в текущую фазу.

На момент завершения сбора все новые материалы находились в `ilang/`, приложение ещё не импортировало это направление. После сбора и концептуального плана владелец отдельно поручил внедрить композицию. Изменение объёма отражено в `../docs/CONCEPT_PLAN.md`; модуль Go подключается явно и выключен по умолчанию.

Хэш извлечённого текста и хэш байтов локального файла учитываются отдельно. На Windows запись text-mode может преобразовать LF в CRLF; `build_catalog.py` проверяет исходный хэш текста, включая обратное однократное преобразование для страниц с исходными CR, и независимо сохраняет SHA-256 байтов. Несовпадение не игнорируется и делает integrity gate неуспешным.

В рабочем Git-каталоге пока нет первого commit; независимая Git-ветка от существующего commit не создаётся посредством фиксации чужих файлов. Исследовательские материалы изолированы в `ilang/`, продуктовый модуль — в `internal/ilang/`. Отдельная Git-ветка пока не создана.
